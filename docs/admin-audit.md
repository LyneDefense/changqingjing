# 后台操作日志

后台侧边栏“系统管理 → 操作日志”提供只读查询。管理员查看全部记录；运营人员只查看自己的记录，服务端对列表和详情均强制执行范围限制。

## 记录范围

记录登录成功/失败、退出登录、保存草稿、预览草稿、发布、下架、删除内容、媒体上传申请与校验、地图位置确认、后台人员维护与密码重置、用户冻结/解冻/删除。不记录输入中的每个字符、普通列表刷新或日志查询本身。排序、图片替换和板块编排在保存草稿时记录字段变更摘要。

成功的业务日志与业务事务一起提交。事务回滚后，另用独立事务记录失败；已有业务记录不会再被请求记录重复覆盖。媒体校验返回 HTTP 200 但业务结果为失败时，仍显示失败。

记录操作时的账号名称、目标名称、来源 IP、浏览器、随机登录批次、追踪号和安全摘要。登录批次独立于真实会话 ID，不能用于认证。密码、令牌、COS 临时凭证、完整手机号和原始请求正文均不进入日志摘要；前端不暴露旧日志的原始 `detail`。

## 筛选与时间

按起止日期、账号、模块、操作、结果筛选，搜索目标名称或 IP；查询参数经过长度、枚举、分页校验，SQL 使用参数绑定及转义通配符。日期边界与页面时间统一为 `Asia/Shanghai`，结束日期包含当天。

历史记录无法补回请求 IP、登录会话、目标名称或变更快照。账号名称可回退到当前账号资料，页面明确标注旧记录。后台没有修改和删除日志的接口。

## IP 与账号共用

生产后端只应经由已配置的 Nginx 入口访问；Nginx 覆写代理地址头，后端取代理处理后的请求地址，不使用表单里的 IP。不要公开后端容器端口。共用网络、VPN、代理及共用账号都会影响追溯，IP/浏览器/批次不能证明自然人身份，建议一人一账号。

## 部署

本功能新增 Flyway V10，只增加日志列和索引，不覆盖历史业务数据。后续通过现有 `deploy/deploy.sh` 部署时执行迁移，同时更新后端和 Web 镜像。数据库管理员仍有直接修改能力；本功能不是数据库级防篡改存证。
