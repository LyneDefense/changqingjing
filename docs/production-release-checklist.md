# 正式发布清单

这份清单区分“代码与制品已准备”和“外部平台已真正发布”。没有真实服务器、域名、微信平台权限和正式内容时，只能完成前者，不能把体验版或正式版标为上线。

## 1. 外部条件

- [ ] 业务域名及接入服务所需备案完成，A 记录指向正式 Ubuntu 服务器。
- [ ] 腾讯云安全组与系统防火墙只向公网开放必要的 80/443；PostgreSQL 端口不开放。
- [ ] 小程序备案、主体认证、服务类目、隐私保护指引和手机号能力均已在微信后台确认。
- [ ] 正式小程序 AppID、AppSecret、手机号调用额度和体验成员已准备。
- [ ] 正式 COS Bucket、最小权限 CAM 服务用户、`prod/` 前缀和生命周期策略已准备。
- [ ] COS CORS 精确允许正式管理后台 Origin；实际 COS HTTPS 域名已加入小程序所需合法域名。
- [ ] 腾讯位置服务 Key 的 Referer 已绑定正式后台；最终视频、图片、景区、产品与合作权益文案已确认。

## 2. 正式服务

按照 [生产式部署](../deploy/README.md) 填写 `deploy/.env.production` 并执行：

```bash
./deploy/deploy.sh bootstrap       # 仅首次
./deploy/deploy.sh status
./deploy/deploy.sh restore-check
./deploy/deploy.sh renew-cert --dry-run
```

首次管理员创建成功后必须关闭 `ADMIN_BOOTSTRAP_ENABLED` 并清除初始化密码。随后由运营人员登录 `https://你的域名/admin/`，逐项录入、预览并发布：首页宣传视频、公司介绍、景区、会员福利产品和合作权益。确认分公司方案、会员体系及个人中心未开放入口仍显示“敬请期待”。

正式服务验收：

- [ ] `/admin/` 和任意后台子路由刷新不出现 404，Cookie 带 Secure，登录、退出与 CSRF 正常。
- [ ] 匿名首页、公司介绍、景区和合作权益接口可用；会员福利正文仍要求登录。
- [ ] 后台上传图片和 MP4 成功，临时凭证无法写入授权 Object Key 之外的位置。
- [ ] 微信真实手机号首次注册、恢复登录、拒绝授权和取消返回路径通过。
- [ ] iOS、Android 的视频播放、长图文、安全区域和景区导航都通过。
- [ ] `status`、每日备份、恢复演练、证书续签演练和失败版本回退记录通过。

## 3. 准备小程序制品

本机的 `miniprogram/project.config.json` 填正式 AppID，但不要提交个人开发者工具配置。然后：

```bash
cp miniprogram/.env.production.local.example miniprogram/.env.production.local
# 填入 https://你的域名/api/v1/app
./scripts/prepare-release.sh 1.0.0 '首版：文旅内容、会员福利与合作权益'
```

该命令会执行全量验收，强制检查 HTTPS 正式 API、正式 AppID、无意外未提交代码和产物中的本地地址，并在 `artifacts/releases/1.0.0/` 生成小程序归档与 SHA-256 发布记录。它不会替你上传、提审或发布。

## 4. 在微信开发者工具 UI 上传

1. 用微信开发者工具打开仓库里的 `miniprogram/` 项目，确认工具读取的是该目录的 `project.config.json`，编译输出为 `dist/`。
2. 正常编译一次，在模拟器和手机预览中确认当前内容、版本接口与正式环境一致。
3. 点击窗口右上角“上传”。在弹窗中填写与制品一致的版本号（例如 `1.0.0`）和简短项目备注，然后确认上传。
4. 上传完成后登录微信公众平台，在版本管理中找到刚上传的开发版本，核对上传者、时间、版本号和备注。
5. 把该开发版本设为体验版，生成体验二维码，只让已配置的体验成员完成上面的正式服务验收；不要拿旧二维码代替本次体验版。
6. 验收记录签字后，在版本管理中对同一个版本提交审核。若审核人员需要操作登录路径，在审核说明中写清入口和授权用途。
7. 审核通过后仍需在平台点击发布。发布完成后，用非开发者普通微信账号重新进入小程序并抽查首页、两个登录入口、景区导航、福利详情和后台内容更新。

上传成功、设置体验版、审核通过和正式发布是四个不同状态；任何一步都不能代替后面的状态。

## 5. 发布记录与回退

每次发布保存以下信息：Git commit、OpenAPI SHA-256、Flyway 最新版本、后端镜像标签、Web 镜像标签、小程序版本号与制品 SHA-256、微信上传／审核／发布时间、执行人和验收结果。

应用问题优先执行 `./deploy/deploy.sh rollback` 回到上一版镜像；数据库迁移坚持前向修复，不自动降级。若已发布小程序有严重问题，先根据微信平台现有能力处理线上版本，同时保持后端对旧客户端兼容，再准备更高版本号重新上传和审核。
